# Проверка person1 на предоставленных видео

Дата: 6 ноября 2026 года. Среда: macOS arm64, Python 3.13.3, выполнение моделей
на CPU. Точные версии находятся в `requirements-macos-arm64.lock.txt`, контрольные
суммы весов — в manifest каждого экспорта и `docs/MODELS.md`.

## Что проверено

- **42 автоматических теста прошли** (`.venv/bin/python -m pytest -q`).
- Реальное кодирование/декодирование MKV, исходные индексы и PTS, переменный шаг
  времени, разные начала камер и обработка позднего фрагмента.
- Силуэты в исходном разрешении, обрезка bbox у границ, сохранение отверстий маски,
  отсутствие скрытого пересчёта координат, сохранение слабых детекций для MOT.
- Качество кропа, нормировка цветовых признаков, разметка одежды SCHP, отсутствие
  одежды как `null`, явная ошибка при отсутствии SCHP вместо скрытой подмены.
- Обмен с person2: пустые кадры, соответствие detection_id, RGB-кропы,
  относительные пути, геометрия изображений и проверка завершённости экспорта.

## Реальные прогоны

`outputs/person2-sample` — первые 100 кадров каждой из пяти камер, **500 кадров,
621 обнаружение**. **350 кропов** прошли текущие эвристики пригодности для ReID.
Это количество наблюдений по кадрам, НЕ число людей и НЕ число треков.

| Камера | Кадры | Детекции | Пригодны для ReID | Цвет верха | Цвет низа |
|---|---:|---:|---:|---:|---:|
| camera_new_1 | 100 | 151 | 28 | 11 | 18 |
| camera_new_2 | 100 | 102 | 100 | 85 | 60 |
| camera_new_3 | 100 | 183 | 91 | 0 | 0 |
| camera_new_4 | 100 | 100 | 100 | 99 | 79 |
| camera_new_5 | 100 | 85 | 31 | 2 | 1 |

Цвет посчитан через **настоящие SCHP ATR18 INT8 веса**. Отсутствующий цвет не
подменяется нулями и не выдаётся за успешное распознавание. На дальнем человеке
камеры 3 SCHP в этом фрагменте не выделил одежду: person2 должен использовать
ReID без цветового слагаемого для таких наблюдений. Геометрический режим `spatial`
доступен явно, но не использовался для цветовых признаков этого архива.

`outputs/later-check` — по 10 кадров каждой камеры, начиная с исходного индекса
1500: ещё **50 кадров и 40 обнаружений**. Проверены фрагменты примерно на
59–80 секундах, в зависимости от камеры. Исходные номера сохранены.

Все **550 кадров** этих двух экспортов проверены по исходным видео: совпадают
индексы и временные метки. Для каждого экспорта валидатор декодировал кропы и
маски и проверил их размер, бинарность, связи записей и счётчики.
Отдельный короткий прогон `final-clock-check` проверил итоговый код на первых
кадрах всех камер с сохранением исходной шкалы времени.

Архив `deliverables/person2-sample.zip` распакован в отдельную папку и проверен
в отдельном окружении только с NumPy/Pillow: PyTorch отсутствует, пример чтения
и полная проверка 500 кадров / 621 обнаружения прошли. В архиве находятся сам
экспорт, лёгкий загрузчик, пример, зависимости и спецификация контракта.

## Время и синхронизация

Размер кадров — 2592×1944. Камеры 1/2/3/5 имеют номинальные 25 FPS, камера 4 —
20 FPS. Видео длятся примерно по 20 минут. Фактические интервалы берутся из PTS,
не из формулы `frame_idx/fps` при наличии PTS.

Первые PTS: 0.785, 0.785, 0.784, 4.629, 5.323 секунды соответственно. Проект
сохраняет эти сдвиги: `timestamp=source_pts-timestamp_origin+camera_offset`.
По умолчанию origin=0 и все добавочные offsets=0. Общая шкала не сбрасывается
отдельно для каждой камеры. Синхронизация часов по событиям в сцене отдельно
не калибровалась; при необходимости это делается через `camera_offsets`.

## Обнаруженный пример ошибки

На камере 3 детектор выделяет фотографии людей на настенном плакате. На первом
кадре их confidence около 0.33 и 0.29. Они сохранены вместе с другими слабыми
детекциями, но не проходят порог пригодности для ReID 0.5. Person2 должен
различать порог рождения локального трека и порог продолжения через слабую
детекцию. Одного признака `usable_for_reid=false` недостаточно, чтобы считать
объект отсутствующим.

Возможное улучшение — проверенная по всему ролику зона исключения плаката
или анализ статичности. В текущей версии такие объекты не удаляются вручную,
и правильность MTMC/подсчёта людей этим модулем не заявляется.

## Границы проверки

Полные двадцатиминутные записи **ещё не обработаны целиком**. Для этого есть
`Обработать_все_видео.command` и команда `python -m perception run` без лимита.
На CPU полный прогон может занять много часов, а кропы и маски займут больше
места, чем сжатые исходные видео. Данные об измеренном времени короткого прогона
лежат в `sample_summary.json`; параллельные проверки влияли на скорость.

Точность детектора и ReID не измерялась по ручной разметке. Тесты подтверждают
работоспособность и целостность передачи. MOT и ReID person2 ещё предстоит
подключить; межкамерная ассоциация и UI относятся к person3.
