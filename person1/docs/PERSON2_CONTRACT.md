# Передача person1 → person2, версия 1.0

Person1 передаёт обнаружения людей и признаки каждого кадра. Person2 связывает их
в локальные треки, вычисляет ReID и сохраняет соответствие `detection_id` →
`local_id`. Глобальные ID и завершение межкамерного трека относятся к person3.

## Что передавать

Передайте **всю папку одного экспорта**, содержащую `manifest.json`, JSONL-файлы,
кропы и маски. Код person2 может находиться в другом проекте. Все пути внутри
экспорта относительны его корню, поэтому папку можно перемещать или архивировать.
Исходное видео нужно передавать отдельно, если оно требуется для интерфейса;
для чтения готовых кропов и масок оно не нужно.

Статус `manifest.status == "complete"` означает, что закончена **запрошенная
выборка**. Это может быть короткий тестовый прогон. Для полного набора проверяйте
`config`, сведения о `coverage` камер и ограничения числа кадров. Не путайте
обработанные 100 кадров с целым видео. `frame_count_expected` может быть `null`:
некоторые контейнеры не сообщают точное число кадров.

Пример расположения (имена папок кропов и масок могут отличаться; читайте пути из
JSON, не собирайте их самостоятельно):

```text
export/
  manifest.json
  cameras/
    camera_1/
      frames.jsonl
      detections.jsonl
      crops/...
      masks/...
```

## Загрузчик

Установите проект по инструкции основного README. Из корня проекта выполните:

```bash
python -m examples.read_for_person2 /полный/путь/к/export --limit 5
```

Минимальное подключение к вашему коду:

```python
from perception.reader import PerceptionReader

reader = PerceptionReader("/полный/путь/к/export")
for camera_id in reader.camera_ids:
    tracker = make_tracker()  # ваша реализация: ОДИН новый трекер на камеру
    for frame in reader.iter_frames(camera_id):
        detections = frame.boxes  # numpy.float32, shape=(N,5)
        # x1, y1, x2, y2, score; все координаты в исходном кадре
        tracks = tracker.update(
            detections,
            (frame.height, frame.width),
            (frame.height, frame.width),
        )
        # Пример выше — сигнатура исходного ByteTrack.
        # Проверьте интерфейс выбранной вами реализации трекера.
        for det in frame.detections:
            if det["usable_for_reid"]:
                rgb_crop = reader.read_crop(det)
                # embedding = ваша_модель_ReID(rgb_crop)
```

В официальном ByteTrack `img_info` и `img_size` участвуют в пересчёте координат.
Здесь оба размера равны исходному размеру `(height, width)`, чтобы не масштабировать
боксы повторно. У сторонних обёрток другая сигнатура `update`; сам формат экспорта
от конкретного трекера не зависит.

`FrameDetections` содержит `camera_id`, `frame_idx`, `timestamp`,
`timestamp_source`, `width`, `height`, список словарей `detections`, кортеж
`detection_ids` и свойство `boxes`. При отсутствии людей `boxes.shape == (0,5)`.
**Вызывайте трекер и на пустых кадрах**, иначе его счётчик пропусков будет неверным.

Нельзя соединять выходы трекера и детекции обычным `zip`: трекер может вернуть
другой порядок или предсказанный бокс без текущей детекции. Сохраняйте ассоциации
трекера либо делайте однозначное геометрическое сопоставление; связывайте
ReID/цвет/маску с `detection_id` конкретного наблюдения.

## Координаты, время, ID

- `camera_id`: строка из латинских букв, цифр, `_` и `-`; уникальна внутри экспорта.
- `frame_idx`: целочисленный индекс **исходного** кадра, начиная с 0. В режиме
  выборки он не перенумеровывается. Если есть пропуски индексов, person2 должен
  учитывать исходное время и пропущенные шаги; базовый прогон обрабатывает каждый кадр.
- `timestamp`: секунды на общей шкале `source_pts - timestamp_origin + camera_offset`.
  По умолчанию общий `timestamp_origin=0`, исходные PTS сохраняются. **Начало
  каждой камеры отдельно не обнуляется**: первые PTS предоставленных файлов
  различаются на несколько секунд. Основной источник — метки видео, не номер кадра.
- `timestamp_source`: `pts` или резервный `fps`.
- `bbox`: целые `[x1, y1, x2, y2]`, координаты **исходного изображения**, начало
  слева сверху. Правая и нижняя границы не включаются, как в NumPy:
  `frame[y1:y2, x1:x2]`. Размер кропа `(x2-x1, y2-y1)`.
- `detection_id`: например `camera_1:f000000042:d000` — первая детекция кадра 42.
  Уникален в пределах экспорта. При другом запуске или модели тот же идентификатор
  может обозначать другой результат; экспорты разных запусков не смешиваются.
- `detection_id` не является `local_id` и не является глобальным `track_id`.

Камеры могут иметь разные FPS. Сравнивайте время, а не равенство `frame_idx` между
камерами. Корректность общего начала и смещений остаётся условием синхронизации.

## Структура файлов

`manifest.json` содержит `schema_version: "1.0"`, `status`, `created_at`, `config`
и массив `cameras`. У каждой камеры обязательны `camera_id`, `source_video`,
`width`, `height`, `fps`, `frame_count_expected`, `frames_path`,
`detections_path`, `status`. У завершённой камеры также есть `processed_frames`
и `detections_count`. Дополнительные поля допустимы и не должны ломать person2.

`frames.jsonl` содержит **одну JSON-строку на каждый обработанный кадр**, включая
пустые. Поля: `camera_id`, `frame_idx`, `timestamp`, `timestamp_source`, `width`,
`height`, `detection_ids`. Строки идут по возрастанию индекса исходного кадра.

`detections.jsonl` содержит одну строку на одного найденного человека. Порядок —
порядок кадров, а внутри кадра — порядок его `detection_ids`. Пример:

```json
{
  "detection_id": "camera_1:f000000042:d000",
  "camera_id": "camera_1",
  "frame_idx": 42,
  "timestamp": 1.68,
  "bbox": [100, 50, 160, 210],
  "score": 0.82,
  "class_id": 0,
  "class_name": "person",
  "mask_path": "cameras/camera_1/masks/example.png",
  "crop_path": "cameras/camera_1/crops/example.jpg",
  "mask_format": "png_crop",
  "mask_origin": [100, 50],
  "mask_size": [60, 160],
  "usable_for_reid": true,
  "quality": {"reasons": []},
  "upper_color_hist": null,
  "lower_color_hist": null,
  "color_method": "none",
  "color_quality": {}
}
```

Это иллюстрация структуры; на диске каждый объект занимает одну строку. При
включённых цветовых признаках вместо `null` записываются массивы из 32 чисел.

## Маски и кропы

Кроп — обычный цветной JPEG исходного изображения, без удаления фона и без
приведения к входному размеру ReID. `read_crop()` выдаёт **RGB**, тогда как
`cv2.imread()` по умолчанию выдаёт BGR. Resize, нормализация и выбор цветового
порядка относятся к входной обработке конкретной ReID-модели person2.

Маска — одноканальный PNG с пикселями `0` (фон) и `255` (человек), того же размера,
что кроп. `read_mask()` возвращает булев массив. Чтобы наложить маску на полный
кадр, вставьте её в `frame[y1:y2, x1:x2]`. Размер маски в JSON — **[width,height]**,
форма массива NumPy — **(height,width)**.

## Качество и цвет

`usable_for_reid=false` исключает только вычисление признаков внешности.
Обнаружение сохраняется и передаётся трекеру. Причины находятся в
`quality.reasons`. Низкая уверенность детектора также не является причиной
самостоятельно удалять строку: ByteTrack может использовать слабые обнаружения
для продолжения существующего трека. Порог экспорта смотрите в `config`.

Цветовые признаки имеют фиксированный формат:

- HSV в соглашении OpenCV: H в `[0,180)`, S и V в `[0,256)`.
- 16 равномерных ячеек H, 8 ячеек S, 8 ячеек V.
- Каждая гистограмма нормируется до суммы 1, затем все три объединяются и делятся
  на 3. Итог — **32 числа, сумма 1**; каждый блок имеет сумму `1/3`.
- `upper_color_hist` — верхняя одежда, `lower_color_hist` — нижняя.
- `null` означает отсутствие надёжного измерения. Это не чёрный цвет и не нулевой вектор.
- `schp_atr_hsv` означает разделение одежды SCHP ATR; `spatial_hsv` — приближение
  по вертикальному положению внутри силуэта; `none` — цвет отключён.

При агрегировании цвета по треклету исключайте `null`. После покомпонентной
медианы заново нормируйте каждый блок и делите конкатенацию на 3. Освещение камер
меняет цвет, поэтому он должен дополнять ReID, а не самостоятельно назначать ID.
Сведения о надёжности областей содержатся в `color_quality`.

## Проверка перед объединением

```python
from perception.validation import validate_export

report = validate_export("/полный/путь/к/export", verify_images=True)
print(report)
```

Проверяются завершённость экспорта, схема, ссылки между файлами, порядок кадров,
время, ID, геометрия, нормировка гистограмм, наличие файлов и итоговые счётчики.
С `verify_images=True` дополнительно декодируются JPEG/PNG и проверяются размеры
и значения масок. Эта проверка подтверждает целостность передачи, но не точность
нейросети. Функция выбрасывает `ContractError` при первой обнаруженной ошибке.

Низкоуровневый `PerceptionReader(..., require_complete=False)` предназначен только
для диагностики незавершённых запусков. Для итоговой склейки используйте значение
по умолчанию. Чтобы загрузчик проверил счётчики и лишние детекции в конце файла,
итератор соответствующей камеры нужно дочитать до конца.
