# Person1: силуэты и признаки для оффлайн MTMC

Модуль читает видео из `Video`, находит людей готовой YOLO11-seg, сохраняет
силуэты, исходные кропы, флаг пригодности для ReID и цвет верхней/нижней одежды.
Результат подключается к person2 через готовый Python-загрузчик.

**Этот модуль не назначает ID треков.** `detection_id` обозначает одно обнаружение
на одном кадре. Person2 делает однокамерный MOT и ReID; person3 — межкамерную
ассоциацию и начало/конец глобального трека.

## Быстрый запуск на этом компьютере

В Finder можно дважды нажать **`Проверить_пример.command`**. Он обработает первые
100 кадров каждой камеры, проверит результат и создаст ZIP для person2.
**`Обработать_все_видео.command`** запускает обработку всех кадров всех записей;
это долгий прогон, при работе на CPU может потребовать много часов.

Из папки проекта:

```bash
.venv/bin/python -m perception inspect
.venv/bin/python -m perception run --max-frames 100 --color-mode spatial --output outputs/quick-check
.venv/bin/python -m perception validate outputs/quick-check
.venv/bin/python -m examples.read_for_person2 outputs/quick-check --limit 3
```

Первый проверочный запуск обрабатывает первые **100 кадров каждой камеры**.
Режим `spatial` оценивает цвета верхней и нижней области силуэта геометрически;
это явно обозначенный упрощённый режим, а не SCHP.

Полная обработка всех видео с SCHP:

```bash
.venv/bin/python -m perception run --output outputs/full-schp
.venv/bin/python -m perception validate outputs/full-schp
```

Выходная папка должна быть новой или пустой: существующие результаты программа
не перезаписывает. Без `--output` создаётся новая папка с датой запуска.
Без `--max-frames` обрабатываются все кадры. Обработка оффлайн, скорость зависит
от компьютера, разрешения нейросети и числа видимых людей.

## Настройка на другом компьютере

Проверенное окружение и результаты проверки описаны в `docs/VALIDATION.md`.
Базовые зависимости перечислены в `pyproject.toml`; для разработки нужен Python
3.11–3.14 с совместимыми PyTorch и ONNX Runtime. На этом Mac используется Python 3.13.

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install --no-user -e '.[test]'
.venv/bin/python -m perception.download_models
```

Точные версии окружения этого Mac записаны в `requirements-macos-arm64.lock.txt`.
Для воспроизведения на macOS arm64 можно сначала установить этот файл с
`pip install --no-user -r requirements-macos-arm64.lock.txt`, затем сам проект
с `pip install --no-user --no-deps -e .`. На другой ОС используйте зависимости
из `pyproject.toml`, поскольку доступность сборок PyTorch зависит от платформы.

Положите веса `yolo11s-seg.pt` в `models`, а проверенные ONNX-веса SCHP ATR —
в `models/schp/schp-atr-18.onnx`. Источники моделей и подготовка SCHP описаны
в `docs/MODELS.md`. При запуске модели не обучаются, видео не отправляется
в сторонний сервис. После установки и загрузки весов инференс выполняется локально.

## Что находится в результате

```text
outputs/имя-запуска/
  manifest.json
  cameras/
    camera_new_1/
      frames.jsonl
      detections.jsonl
      crops/*.jpg
      masks/*.png
      preview.jpg
      preview.mp4
    camera_new_2/...
```

- `manifest.json`: версия формата, исходные файлы, параметры, версии библиотек,
  контрольные суммы моделей, счётчики и статус завершения.
- `frames.jsonl`: запись **каждого кадра**, включая кадры без людей.
- `detections.jsonl`: bbox, confidence, пути к маске/кропу, качество и признаки цвета.
- `crops`: оригинальные цветные изображения людей без удаления фона и без resize для ReID.
- `masks`: бинарные PNG 0/255 в координатах кропа.
- `preview.jpg`: первый кадр камеры с обнаружениями; зелёный — кроп пригоден для ReID,
  оранжевый — есть причины не использовать его внешность.
- `preview.mp4`: начало видео с силуэтами для визуальной проверки. Это не итоговый
  интерфейс MTMC; подпись `det` — номер обнаружения в текущем кадре, не ID трека.

Если на камере никого не обнаружено, `preview.jpg` может отсутствовать. Видео
предпросмотра использует номинальный FPS; точные временные метки для алгоритма
находятся в JSONL, что особенно важно для видео с переменным FPS.

`status=complete` означает завершение запрошенного диапазона. При тесте с
`--max-frames` это не весь ролик: проверяйте `coverage` у камер. Если лимит кадров
достигнут ровно на конце ролика, `whole_video` консервативно остаётся `false`.
Незавершённые/ошибочные экспорты не принимаются загрузчиком person2 по умолчанию.

## Как соединить с person2

Передайте person2 **всю папку результата**, а также `perception/reader.py`,
`perception/validation.py` и `docs/PERSON2_CONTRACT.md` либо весь исходный проект.
Для одного только загрузчика достаточно NumPy и Pillow; запускать YOLO повторно
ему не нужно. Пути к кропам и маскам относительны корню экспорта.

```python
from perception.reader import PerceptionReader

reader = PerceptionReader("outputs/quick-check")
for camera_id in reader.camera_ids:
    for frame in reader.iter_frames(camera_id):
        boxes = frame.boxes  # float32, N x 5: x1, y1, x2, y2, score
        # Здесь person2 вызывает свой трекер, в том числе при N == 0.
        for detection in frame.detections:
            if detection["usable_for_reid"]:
                rgb = reader.read_crop(detection)
                # Здесь person2 вычисляет SOLIDER/другой ReID.
```

Подробный контракт, пример вызова исходного ByteTrack, временные метки и правила
сопоставления ID — в [PERSON2_CONTRACT.md](docs/PERSON2_CONTRACT.md).
Нельзя сопоставлять выход трекера и детекции простым `zip`: порядок и состав
могут отличаться. Сохраняйте ассоциацию `detection_id → local_id`.

Готовый архив для передачи (включает данные, лёгкий загрузчик и инструкцию):

```bash
.venv/bin/python -m perception pack outputs/quick-check deliverables/person2-sample.zip
```

Исходные видео и тяжёлые модели в архив не входят. Person2 распаковывает его,
устанавливает NumPy/Pillow и запускает пример из `README.txt` внутри архива.

## Настройки

`configs/default.json` содержит настройки всех этапов. Пути в нём считаются
относительно корня проекта. Имена камер совпадают с именами видео без расширения.
Допустимы латинские буквы, цифры, `_` и `-`; одинаковые имена камер запрещены.

```bash
.venv/bin/python -m perception run --camera camera_new_1 --max-frames 50 --color-mode spatial
.venv/bin/python -m perception run --start-frame 1500 --max-frames 100 --color-mode spatial
.venv/bin/python -m perception run --device cpu --imgsz 640 --color-mode none
```

- `device=auto`: CUDA при наличии, иначе Apple MPS, иначе CPU. Можно задать явно.
- `imgsz=960`: размер входа YOLO; bbox и маски возвращаются в исходных координатах.
- `confidence=0.1`: сохраняем слабые обнаружения для второго этапа ByteTrack.
  Этот порог согласуйте с person2; повышение порога удаляет данные до трекера.
- `reid_min_confidence=0.5`: слабые обнаружения сохраняются, но не используются
  для сравнения внешности и по умолчанию для дорогой обработки цвета.
- `color_mode=schp`: разделение одежды SCHP ATR и HSV-гистограммы.
- `color_mode=spatial`: геометрическое приближение цвета по силуэту для быстрого старта.
- `color_mode=none`: цвета отключены, оба признака `null`.
- `color_only_usable=true`: затраты на SCHP только для пригодных кропов.
  У остальных обнаружений остаются bbox/маски/кропы, цвет — `null`.
- `quality`: настраиваемые пороги размера, резкости, доли маски и границ кадра.
  Это эвристики качества, не доказательство наличия/отсутствия окклюзии.
- `camera_offsets`: `{ "camera_new_2": 0.0 }` — смещение времени в секундах.
  Метка — **исходный PTS кадра − общий `timestamp_origin` + смещение камеры**.
- `timestamp_origin=0.0`: сохраняем исходную шкалу PTS. У этих файлов первые PTS
  отличаются: камеры 1/2 — 0.785 с, камера 3 — 0.784 с, камера 4 — 4.629 с,
  камера 5 — 5.323 с. Их нельзя независимо обнулять. Если нужен ноль в начале
  самого раннего файла, установите общий origin=0.784 для всех запусков.
  Согласованность часов камер по сценам отдельно не калибровалась; при необходимости
  корректируйте `camera_offsets`, сохраняя исходную шкалу и записывая настройку.
- `preview_frames=250`: длина проверочного видео в кадрах; `0` отключает видео.
- `start_frame=0`: можно начать выбранный фрагмент позже; исходные номера кадров
  и временные метки сохраняются. Предыдущие кадры декодируются без нейросети,
  чтобы не подменять точное время приближением по FPS. Одинаковый start_frame
  означает разное время на камерах с разным FPS.

Кроп с `usable_for_reid=false` сохраняется для MOT. Пустая маска или вырожденный
бокс не экспортируются как силуэт; число таких случаев видно в `diagnostics`.
Если SCHP выбран, но модель отсутствует/не запускается, обработка завершается
с ошибкой — скрытой подмены SCHP упрощённым методом нет.

## Проверка и ограничения

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m perception validate outputs/quick-check
```

Валидатор проверяет связность записей, геометрию, изображения, ID, времена,
гистограммы и итоговые счётчики. Он не измеряет точность детектора. Визуально
проверьте сидящих людей, пересечения, края кадра и дальние планы.

Предварительно обученная модель может пропускать сильно перекрытого человека,
ошибаться на отражениях или путать предмет с человеком. SCHP также может неверно
разделять одежду; цвета разных камер меняются из-за освещения. Нельзя сравнивать
гистограммы как надёжное доказательство идентичности человека.

Готовые компоненты: YOLO11-seg/Ultralytics, PyTorch, SCHP, ONNX Runtime, PyAV,
OpenCV, NumPy. Командная реализация: обработка видео и времени, контракт,
сохранение силуэтов и кропов, эвристики качества, извлечение гистограмм,
валидация и загрузчик. Обучения, MOT и MTMC в этом модуле нет.

Источники и лицензии перечислены в `docs/MODELS.md`.
